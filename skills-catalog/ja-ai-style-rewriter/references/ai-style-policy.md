# LLM文体除去の校正ポリシー

このファイルは `ja-ai-style-rewriter` の日常運用ルールを調整するための設定です。
`SKILL.md` 本体を大きく変えずに、運用ルールだけ更新したいときに編集します。

## 0. 主目的
- 主目的は「日本語としての自然さ」を保ちながら、LLM が生成した日本語ドラフトに出やすい文体の癖を下げること。
- ただし事実保持を最優先し、意味改変はしない。

## 1. 非対話の運用
- 通常ケースでは承認待ちを挟まず最後まで実行する。
- 例外として、次の場合だけ確認する。
  - 対象ファイルパスが不明
  - ユーザー指示が論理的に両立しない

## 2. 記号・表記の例外
基本方針は「全般禁止」ではなく「不自然な乱用を避ける」。
- かぎかっこは強調目的で使わない。引用、用語の定義、固有名称に限って使う。
- `〜したい、ということだ` `〜である、という点だ` のように、述部の直前を読点で切る書き方は原則避ける。不自然な強調や説明書きの調子が出やすいため、`〜したいということだ` のように続けて書くか、必要なら文を分ける。

既定で許可:
- URL 表記（`https://...`）
- パス表記（`src/app.ts`）
- バージョン表記（`v1.2.3`）
- 日付・時刻・単位の表記（`2026-02-15`、`10:30`、`20%`）
- 既存文書スタイル上必要な Markdown 記法

ユーザー指定がある場合に許可:
- 箇条書き
- 丸かっこでの補足
- 比較表

## 3. 事実保持チェックリスト
最終反映前に次を確認する。
- 固有名詞が変わっていない
- 数値・日付・単位が変わっていない
- 因果関係の意味が変わっていない
- 新しい主張・事例・出典を追加していない

## 4. LLM文体判定チェック
編集前後を見比べ、次の傾向が弱まっているかを確認する。
- 定型導入句や説明書的ラベルの多用
- 同一語尾の連続
- 抽象語偏重で動作が見えない文
- 保険的な言い回しの重複
- 文章テンポの均質化
- 専門的な内容に対して、何にでも使いやすい口語的な動詞が混ざる文体のちぐはぐさ
- 評価語だけが並び、条件や根拠が見えない文
- `重要なのは` `ポイントは` のような段落ラベルで話を始める文の反復
- `場合による` で判断を読者に返して終わる文

## 5. 用語・文体ポリシー
- 造語を一律禁止しない。英語を直訳したような不自然な造語は使わず、標準的な表現へ置換する。
- 文脈にない概念、略語、前提を新規導入しない。
- 初出の略語は展開形を添える。一般に通じにくい略語は使わない。
- 標準的な日本語が不確実な場合は、英語原語を使い短い説明を添える。
- `見ます` `出ます` `言えます` `なります` のように、対象や動きがぼやけやすい動詞で安易に文を閉じない。対象や動きが見える具体表現を優先する。
- 技術的・専門的な内容では、説明対象のレベルに合わせて語彙を選ぶ。専門語や漢語で書くべき箇所を、`効く` `働く` `乗せる` `やる` `持つ` のような、何にでも使いやすい口語的な動詞でぼかさない。
- 具体性の低い動詞を差し替えるときは、意味が狭まっても具体性が上がる語を優先する。
  - 例: `効く` -> `有効である` `効果を示す` `機能する`
  - 例: `働く` -> `作用する` `機能する` `抑制する`
  - 例: `乗せる` -> `反映する` `組み込む` `搭載する`
  - 例: `やる` -> `実行する` `検証する` `運用する`
- `〜ではない` `〜と言いたいわけではない` のような防御的な否定から文を始めない。必要な対比や限定を除き、肯定文で言い切る。
- `重要` `有効` `最適` `柔軟` のような抽象的な評価語だけで終わらせない。可能なら条件、数値、比較対象、具体例に落とす。
- `重要なのは` `ポイントは` `大事なのは` のような言い回しを段落の起点として続けない。ラベルを置く代わりに、その段落で述べたい判断や条件をそのまま書く。
- `場合による` `一概には言えない` `ケースバイケース` を結論として置かない。条件を示したうえで、その文書としての判断や推奨を残す。
- 読者への配慮を理由に、意味を削る方向の過度な平易化をしない。わかりやすさより、まず何が起きるかが見える語を選ぶ。

## 6. 注意カテゴリ
- LLM 由来の定型句や空疎な形容語の多用を避ける。
- 次の語は一律禁止しないが、文脈に応じて置換を検討する。
  - 革新的
  - 最先端
  - シームレス
  - 圧倒的
  - 劇的
  - 育てる
  - 触る
  - 効く
  - 働く
  - 乗せる
  - やる
  - 持つ
- 「育てる」「触る」は何にでも使いやすい動詞として使わず、必要に応じて具体動詞へ置換する。
  - 例: 育てる -> 改善する、整備する、更新する、強化する
  - 例: 触る -> 編集する、変更する、実行する、検証する、確認する
- `効く` `働く` `乗せる` `やる` `持つ` も、専門的な説明では何にでも使いやすい動詞として使わない。対象と作用が見える語へ置換する。
- 次の定型表現は、事実上の判断回避になっていないか確認する。
  - `場合による`
  - `一概には言えない`
  - `ケースバイケース`
  - `メリット・デメリットがある`

## 7. フォールバック
元文が短すぎる、または制約が厳しすぎる場合は、最小限の修正に留める。
